The API itself is in [`cv-api.d.ts`](cv-api.d.ts) — every global, method, property, constant and
database-derived name, with descriptions and examples. **Read that file for anything you need to
call.** This file covers only what a type declaration cannot say: how Cabinet Vision executes the
code, and the handful of rules that make correct-looking JavaScript behave wrongly.

Read [`AGENTS.md`](AGENTS.md) first if you have not.

## Execution model

A UCS:JS is a **function body**, not a script. Cabinet Vision primes a JavaScript engine with the
current objects and runs your code once per matching object.

```js
// legal, and the normal way to bail out early
if (_cab.CLASS != ASM_CLASS_BASE) {
    return;
}
```

The mirror wraps the file in `(function () { … })();` for exactly this reason, so the TypeScript
service agrees that `return` is legal. Do not remove a top-level `return`, and do not remove the
wrapper or the `//~` header above it — see rule 4 in [`AGENTS.md`](AGENTS.md).

Two objects are supplied:

| global | is |
|---|---|
| `_this` | the object the standard is running against — the UCS:JS equivalent of the UCS:M `For Each` object |
| `_cab` | the assembly that owns it — the equivalent of the UCS:M `Cab` object |

Both are `CVAsmManaged`.

## The `For Each` is not in the code

In UCS:M the condition that selects objects is a statement in the code:

```ucsm
;UCS:M
For Each AS|FS Part
```

In UCS:JS it is a **property of the standard**, set in the UCS Manager UI. Cabinet Vision evaluates
it *before* the script runs and only executes the script if it matches. There is no `For Each` in
the JavaScript, and writing one is an error. The same applies to the assembly-class, construction
method, end-type and object-condition filters.

If a change requires a different `For Each` or filter, say so — it cannot be made from these files.

## Public variables are not declared in the code

In UCS:M, `Public NAME = value` is a line of code. In UCS:JS, public variables are defined in the
UCS Manager UI, and the runtime injects each one as a plain global you can read:

```js
_this.DX = PUB_VALUE;   // PUB_VALUE was defined in the UCS Manager, not here
```

They will not resolve in the editor, because the extension cannot know they exist. That is expected;
do not "fix" it by declaring them. To add a public variable, the user must do it in Cabinet Vision.

## A `var` is not a parameter — the most common mistake

In UCS:M every variable *is* a parameter on the current object, so it can appear inside an equation.
In UCS:JS a `var` is an ordinary JavaScript value that Cabinet Vision knows nothing about.

```js
var MY_VALUE = 5;
_this.DY = MY_VALUE;           // fine - assigns the number 5
_this.DZ = 'DX + MY_VALUE';    // BROKEN - CV evaluates this string and has never heard of MY_VALUE
_this.DZ = 'DX + ' + MY_VALUE; // fine - the number is baked into the equation before CV sees it
```

Any string assigned to a parameter, or passed to `Evaluate`, is a **Cabinet Vision equation**
evaluated by CV using UCS:M rules — not JavaScript. Only names CV can resolve in the object tree are
valid inside it. If you want a JavaScript value in an equation, concatenate it in.

To create a real parameter, set one:

```js
_this.SetParameter('MY_PARAM', 5);
var v = _this.GetParameterValue('MY_PARAM');
```

## Parameters: property or method

The common parameters are exposed as properties, which is shorthand for the method form. Both are
equivalent; the property is preferred where it exists (see `CVAsmManaged` in `cv-api.d.ts`).

```js
_this.DX = 5;                       // property
_this.SetParameter('DX', 5);        // method - identical effect
_this.SetParameter('PRICE', price, VAL_CURRENCY);   // a value type is often required
```

Reading works the same way: `_this.DX` or `_this.GetParameterValue('DX')`. Use
`GetParameterValue` for user parameters, which have no property.

**Cache reads.** Every `GetParameterValue` or property read may trigger a full equation evaluation
in Cabinet Vision. Read once into a `var` and reuse it:

```js
var length = _this.GetParameterValue('DY');   // evaluated once
if (length < 20)      { … }
else if (length > 50) { … }
```

## Case sensitivity

UCS:M is case insensitive. JavaScript is not, and neither are the CV object names:

```js
_this.DX = 5;    // correct
_this.Dx = 5;    // wrong - creates a stray JS property, sets nothing
if (_Cab.DX)     // wrong - _Cab is not defined
```

The exception is anything inside a string that CV evaluates, because CV itself is case insensitive:

```js
_this.DX = 'dy / 2';            // fine
_this.Evaluate('(DX + dy) / 2'); // fine
```

## Comparing measurements

Cabinet Vision compares floating point parameter values with a tolerance of `1.19e-04`. Plain
JavaScript `==` and `<` do not, so a comparison that CV considers equal can come out false. Use
`_cvMath` for any comparison of two measurements:

```js
if (_cvMath.isEQ(_this.DX, _cab.DX))  { … }
if (_cvMath.isGTE(_this.DY, 24))      { … }
if (_cvMath.isZero(_this.SCB))        { … }
```

`isEQ`, `isGT`, `isGTE`, `isLT`, `isLTE`, `isZero`. Use `==` freely on IDs, integers, constants and
strings — the tolerance only matters for measurements.

## Units

Values are in the job's current unit of measurement. Convert explicitly rather than hard-coding a
conversion:

```js
var mm  = _cvMath.Metric(1);    // inches -> mm  (x 25.4)
var inch = _cvMath.Imperial(32); // mm -> inches (/ 25.4)
```

`Imperial()` and `Metric()` also exist as bare globals routing to the same methods.

## Constants

Constants are declared in `cv-api.d.ts` as branded number types, so a parameter that expects an
assembly class will only accept an `ASM_CLASS_*` and the editor will list them. Use the constant,
never its numeric value:

```js
if (_cab.CLASS == ASM_CLASS_BASE && _cab.TYPE == ASM_TYPE_STANDARD) { … }
```

Looking an ID up by name is `QueryID` with an `ID_*` constant:

```js
if (_cab.GetParameterValue('CONSTID') == _this.QueryID(ID_ASSEMBLYCONSTRUCTION, 'Frameless')) { … }
```

## Libraries

Files in `lib/` are shared code. Each is bound to a global named `_` plus the library's lowercased
name, declared by the file's sentinel line, and callable from every standard:

```js
// in lib/Helpers.ucs.js, between the sentinels
Round32(value) {
    return Math.round(value / 32) * 32;
}
```

```js
// in any ucs/*.ucs.js
_this.DY = _helpers.Round32(_this.DY);
```

The body of a library is a **class body**, so its members are written as methods without `function`,
separated by nothing, and share state through `this`. A regular standard is a function body and
follows normal JavaScript.

Only add a library method when more than one standard needs it. Changing an existing library method
changes the behaviour of every standard that calls it — check the callers first (they are all under
`ucs/`, so a search finds them).

## What is not available

The Cabinet Vision script engine is not a browser and not Node:

- No DOM — no `window`, `document`, `localStorage`, `fetch`, `XMLHttpRequest`.
- No modules — no `require`, `import` or `export`. Shared code goes in `lib/`.
- No file system, network or process access.
- No `setTimeout` / `setInterval`; the script runs synchronously and must finish.
- `alert()` exists at runtime but is not declared in `cv-api.d.ts`; call `_cvSystem.Alert()` instead,
  which is declared and does the same thing.

Standard ES2017 JavaScript is available: `Math`, `String`, `Array`, `Map`, `Set`, `JSON`, arrow
functions, `let`/`const`, template literals, destructuring. Ordinary `function` declarations work and
are the way to factor logic within one standard — UCS:M has no equivalent.

## String helpers

`_cvString` exposes Cabinet Vision's own string handling, which is case insensitive by default and
supports CV's wildcards (`*` any run of characters, `?` one character):

```js
_cvString.isEQ('abc', 'ABC');            // true
_cvString.isEQ('abc', 'ABC', true);      // false - case checked
_cvString.isEQN('abc123', 'ABC', 3);     // true - first 3 characters
_cvString.isEQWC(_cab.NAME, 'B*D');      // true for B24D, B18D, B9D
_cvString.FieldString('ab,cd,ef', 3);    // 'ef'
```

Prefer these over JavaScript string comparison when matching CV names — assembly and part names are
matched case insensitively everywhere else in the program.

## A worked translation

UCS:M:

```ucsm
;Adjust Adjustable/Fixed Shelf
For Each AS|FS Part
If Cab.ConstID = AsmConstID('Frameless') Then
 If Cab.DX >= 25 Then
  If Cab.Type = ASM_TYPE_STANDARD Then
   DY += 10
  End If
 End If
End If
```

UCS:JS — the `For Each AS|FS Part` becomes the standard's property, and the rest becomes code:

```js
//Adjust Adjustable/Fixed Shelf
if (_cab.GetParameterValue('CONSTID') == _this.QueryID(ID_ASSEMBLYCONSTRUCTION, 'Frameless')) {
    if (_cvMath.isGTE(_cab.DX, 25)) {
        if (_cab.TYPE == ASM_TYPE_STANDARD) {
            _this.DY += 10;
        }
    }
}
```

Note what changed: the implicit `DY` became `_this.DY`, the implicit `Cab` became `_cab`, and the
measurement comparison `>= 25` became `_cvMath.isGTE`.

UCS:M is Cabinet Vision's own macro language, stored in `ucs/*.ucsm`. It resembles BASIC but is much
smaller, and the difference that matters most is this: **there are no variables.** Every assignment
writes a *parameter* onto an object in the model, and every bare name in an expression is looked up
in the object tree.

Read [`AGENTS.md`](AGENTS.md) first if you have not. For the JavaScript alternative see
[`ucsjs-reference.md`](ucsjs-reference.md).

## Shape of a standard

```ucsm
;Links Board to Adjustable & Fixed Shelves      <- the first line MUST be a comment
For Each AS|FS Part                             <- what this standard runs on
If Cab.Class == ASM_CLASS_BASE Then             <- filters
  DY += 10                                      <- the work
End If
```

- `;` starts a comment; everything after it on the line is ignored.
- **The first line of every UCS must be a comment.** This is enforced by Cabinet Vision.
- The four `;~` lines at the top of the file are a generated header, not part of the standard. Leave
  them alone and start reading at the line below them.
- The language is **case insensitive** throughout — `DX`, `Dx` and `dx` are the same parameter.
- One statement per line. There is no statement separator and no line continuation.

## `For Each`

```ucsm
For Each <names> <ObjectType>
```

`<names>` is one or more internal object names separated by `|`, and may use the wildcards `*` (any
run of characters) and `?` (exactly one character). `<ObjectType>` is one of the types listed below.

```ucsm
For Each AS|FS Part          ; adjustable and fixed shelves
For Each *HBORE Linebore     ; every construction bore
For Each CAB Assembly        ; the assembly itself
```

Any parameter in the code that is **not** prefixed with `.` or `:` refers to the `For Each` object.
So in `For Each AS Part`, a bare `DY` is the shelf's `DY`.

`this` is a substitute for whatever matched the `For Each`, which is how you write one condition
that covers several alternatives:

```ucsm
For Each DWR_OPEN|DOR_OPEN Part
If this.DOR.S_DSLAB.DX > 5 Then
  ; runs for whichever of the two matched
End If
```

## Moving around the object tree

Bare names are looked up on the `For Each` object. To reach anything else, navigate:

| operator | meaning |
|---|---|
| `.` | go **down** one level, into a child — `Cab.Case.LU.DZ` |
| `:` | go **up** one level, to the parent — `:DY` is the parent's `DY`, `::DX` the grandparent's |
| `@n` | select among siblings of the same name — `MR@2` is the second `MR` |
| `{ }` | substitute a parameter's value into a name — `{_NAME}@{_COUNT}` |
| `Cab` | the assembly that owns the current object, from anywhere |
| `Owner` | the part an operation is attached to |

`Case`, `Face` and `Interior` are container objects inside an assembly: `Face` holds the face frame,
doors and drawer fronts; `Case` holds the carcase parts. Referencing `Face.Z` rather than the
assembly's own `Z` automatically accounts for the face frame — prefer it.

Names can be built at run time with `{ }`, which is the only looping idiom the language has:

```ucsm
_COUNT = 1
_NAME<text> = 'AS'
While CAB.INTERIOR.{_NAME}@{_COUNT}.DX > 0 Do
     If CAB.INTERIOR.{_NAME}@{_COUNT}.ID == ID Then
          _FOUND := ID
          Exit
     End If
     _COUNT += 1
End While
```

## How a parameter is found — and why a typo returns 0

When Cabinet Vision resolves a name it looks on the object, then the object's parent, then *its*
parent, and so on to the top of the job, stopping at the first hit. A value set at room level is
therefore inherited by every assembly under it unless one of them overrides it.

**If the name is found nowhere, the result is `0` — not an error.** A misspelled parameter silently
evaluates to zero and the part collapses or moves to the origin. When a standard "does nothing" or a
part disappears, suspect a name before you suspect the logic. Check existence explicitly:

```ucsm
If U_DWStrip == null Then
     U_DWStrip<bool> = 0
End If
```

## Assignment

| operator | meaning |
|---|---|
| `=` | assign — the right-hand side is stored as an **equation** and re-evaluated on every rebuild |
| `:=` | compute now — evaluate once and store the resulting **value** |
| `+=` `-=` `*=` `/=` | adjust the current value |
| `Adjust Add (X)` | add X to the current value (equivalent long form) |
| `Adjust Mult (X)` | multiply the current value by X |
| `Delete X` | remove the parameter `X` from the object |

The difference between `=` and `:=` is the single most important choice in the language. `DX = :DY`
keeps the part the same length as its parent forever; `DX := :DY` freezes today's number.

Assigning to a parameter that does not exist **creates** it. There is no declaration.

Special assignments:

- `QTY = 0` deletes the object.
- `Visible = True` makes a newly created part appear in the model and on the cut list.
- `REPT` is the number of holes in a boring operation, `SPCNG` the spacing between them.
- `UCSMOD = 1` on a manually added part makes standards apply to it. Standards only touch system
  parts otherwise. It has no effect on parts added by a standard — size those correctly when you
  create them.

## Value types

A parameter's type is set by suffixing the name with a type tag on assignment. Measurement is the
default and is the only type converted between imperial and metric.

{{VALUE_TYPES}}

`<style>` and `<desc>` control how the parameter is presented to the user rather than what it holds:

```ucsm
U_DWStrip<bool> = 0                        ; boolean, default false
U_DWStrip<style> = 1                       ; 1 = Attribute: prompts in the sidebar
U_DWStrip<desc> = 'Add Dishwasher Strip'   ; the prompt text
```

`<style>` values are `0` = Value (set by the standard, visible in the Object Tree), `1` = Attribute
(user-promptable trigger), `2` = Note (user-editable text, available to CAD text lookups).

Text parameters can interpolate other parameters with `{ }`:

```ucsm
NAME = w{DX}h{DY}d{DZ}
COMMENT = {name} ({job.name})
```

## Operators

| | |
|---|---|
| arithmetic | `+` `-` `*` `/` `%` (modulus) `^` (power), unary `+` `-` |
| comparison | `==` `!=` `<` `>` `<=` `>=` |
| logical | `&` and `and`, `\|` and `or`, `!` (not) |
| null test | `X == null` — true when the parameter does not exist |

Use `==` for comparison. `=` is assignment; some existing standards use it inside `If` and are
tolerated, but `==` is correct and is required in Object Tree conditions.

## Control structures

{{CONTROL_STRUCTURES}}

`Exit` leaves the standard immediately.

```ucsm
If <condition> Then
     …
Else
     …
End If

While <condition> Do
     …
End While
```

There is no `ElseIf`, no `For` loop, no `Select`/`Case` and no user-defined function. Nested `If`
blocks are the normal way to express several conditions, and existing standards nest deeply — match
that rather than trying to flatten it.

## Creating objects

```ucsm
Dim <Name> as New <ObjectType>
```

The name must be unique within the standard. Set the new object's parameters by prefixing them with
its name:

```ucsm
Dim BOARD as New Part
BOARD.Visible = True
BOARD.DX = 3
BOARD.DY = :DY + 0
BOARD.X = 0
BOARD.Y = :DZ + 0
BOARD.Z = :DX + 0
BOARD.AZ<deg> = -90
BOARD.QTY<int> = 3
```

An **operation must be attached to a part**, never to another operation. When a standard runs on an
operation and creates another, re-attach it:

```ucsm
For Each LFVBORE Operation
Dim VBORE as New Linebore
VBORE.Owner = Owner        ; attach to the part that owns the operation, not to the operation
VBORE.Visible = True
```

`Hardware` objects must be used with connectors.

## Public variables

```ucsm
Public <Name>[ ] [:]= <DefaultValue> [;description]
```

One per line. They are extracted automatically and shown in the UCS Manager so the user can change
the value without editing code.

```ucsm
Public BSpacing = imp(32)     ;Bore spacing
Public Oversized := DX > 40   ;When is the cabinet oversized?
```

Once the user edits a public variable in the property list, a modified flag is set in the database
and the value always comes from the property list from then on — editing the default in the code no
longer has any effect. The workaround is to rename the variable.

## Units and conversion

| | |
|---|---|
| `Imp(X)` | metric to imperial (divides by 25.4) — `Imp(32)` is 32 mm |
| `Xmm` | a metric literal — `300mm` |
| `Xin` | an imperial literal — `12in` |

Wrap other functions around `Imp()` for metric work: `ABS(Imp(100))`.

## Referencing construction method standards

`_CV:238` is the value entered for construction method standard number 238 (in that example, toe
kick height). Find the number in the Assembly Manager wizard, shown as `[Standard #238]`. Many
values are only present on an assembly when overridden, so referencing the construction standard is
often more reliable than referencing the parameter.

{{SPECIAL_OBJECTS}}

Valid forms include `_m:matid`, `tr._m:schedid`, `face.mr@2._m:dz`, `cab.face.mr@2._m:matid`.

## Wildcards

`*` matches any run of characters, `?` matches exactly one. Both work in `For Each` names and in
name comparisons, and several may appear in one string (`W*3?D*BB`).

Note how `*` is matched: on encountering `*` the program searches the rest of the string for the
next literal character and compares from there. `N*BORE` therefore does **not** match
`NoooBoooBORE`.

## Evaluation order

Standards run in the order they appear in the UCS list, and each one processes the assembly in
object-tree order before the next one starts — UCS #1 for every object, then UCS #2 for every
object. Within an assembly, children of an earlier branch are processed before the parent of a later
branch.

Generation is a two-pass process: the assembly is built and connections created, standards run for
the assembly and its parts and connections, parts are generated and relocated, the connector creates
operations, and then standards run again for the connection-generated objects.

Two consequences: a standard cannot rely on anything a *later* standard does, and reordering the
list changes behaviour. If a change requires a different position in the list, say so — it is set in
Cabinet Vision, not in these files.

## The basic nine parameters

Almost every object has these, and they are the only ones stored per object:

| | |
|---|---|
| `X` `Y` `Z` | position, **relative to the parent**. X right (+) / left (−), Y up (+) / down (−), Z forward (+) / back (−) |
| `DX` `DY` `DZ` | width, length or height, thickness or depth |
| `AX` `AY` `AZ` | rotation about each axis, in degrees, applied in the order X then Y then Z |

The axes do not move with the part, which is why rotations rarely read the way you expect — an
adjustable shelf is `AX = -90, AY = -90`, not `AX = -90, AZ = -90`. A part's thickness comes from its
material and needs no equation.

## Worked example

```ucsm
;Links Bottom Rail to Bottom of Upper Assembly with Bottom Scribe
For Each BO Part

 If Cab.Class == ASM_CLASS_UPPER Then
  If CAB.SCB > 0 Then          ;assembly has a bottom scribe

   ;initialise, because a name that is never found evaluates to 0 anyway
   LendThick = 0
   RendThick = 0

   If LEND == 2 Then
    LendThick = CAB.CASE.LU.DZ
   End If
   If REND == 2 Then
    RendThick = CAB.CASE.RU.DZ
   End If

   Dim BR as New Part
   BR.Visible = True
   BR.DX = CAB.SCB
   BR.DY = :DY + LendThick + RendThick
   BR.X = DZ
   BR.Y = 0 - LendThick
   BR.Z = :DZ
   BR.AY = -90

  End If
 End If
```
